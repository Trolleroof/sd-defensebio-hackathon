# Motion-robust pulse estimation — retrospective research task v1

Develop a reproducible streaming heart-rate estimator using wrist optical pulse and three-axis acceleration. Every two seconds, predict mean heart rate over the trailing eight seconds, in bpm, with a 90% prediction interval. Use only samples available at that update. You may design preprocessing, features, model architecture, loss, fitting and causal temporal state. Improve on the provided baseline within the published resources. ECG provides training labels and is unavailable at inference. Select and submit your final executable artifact using public development evidence.

Read `DATA_DICTIONARY.md` and `example-request.json`. Run from a writable workspace containing only the public training/development exports. Training data include ECG-derived labels. Development signals and the eligible update list are public; their labels are controller-owned. Test recordings and labels never enter your workspace. Do not use filenames or person IDs as model features. Fit preprocessing on training people. Paired devices belong to the same person; no random window splits. ECG, vendor HR, activity labels, and Empatica channels are unavailable at inference. This is the sensor-acquisition-time tier: gateway receipt latency is not modeled.

Submit `artifact/inference.py` implementing `predict(artifact_dir, request)`. Return exactly `mean_bpm, lower_bpm, upper_bpm, state`. All numeric values must be finite; lower <= mean <= upper. State is JSON under 16 KiB. The runner sends one request at a time and resets the worker/state between people and bouts. Load fitted parameters from the artifact; do not fit from evaluation recordings. Include training source, JSON/NPZ fitted parameters (untrusted serialization stays inside worker), requirements lock, seeds, exact reproduction command, and evidence report. The final selected artifact is immutable and verified by hashes.

Baseline API: `prepare(source_root, output_root, split_manifest)`, `train(train_manifest, calibration_manifest, output_dir, seed)`, `predict(artifact_dir, request)`, `score(reference_records, predictions, scoring_config)`. Task-specific baseline implementations are examples; your estimator is unrestricted within the allowed inputs and compute. Training-median, spectral, motion-aware spectral tracking and ridge regression are provided. Intervals use training residual quantiles; coverage is measured, not promised. Calibration manifests must contain permitted training people; no new-person ECG calibration tier exists in this release.

Provisional limits: CPU only, two hours elapsed from session creation, 30 development calls including failed calls, up to 8 cores and 32 GiB capped by host allocation. Commands and descendants count against elapsed time. No network in workers. Cache dependencies and allowed assets before starting. Scored runs require the digest-pinned Docker worker. Local macOS development has privacy and timeout checks but lacks hard memory/CPU-core isolation and is not a scored resource-compliant run. Freeze the declared incumbent at 15/30/60/120 minutes; final selection uses public development results. Private checkpoint/final scores provide no participant feedback. Never choose a final candidate from private results.

Primary loss is MAE in bpm: mean windows within each bout, mean bouts within each person, equal mean across people. All frozen eligible windows require predictions. A missing/nonfinite/unordered prediction invalidates the entire attempt (loss and skill null). Report activity MAE, worst activity, fraction >10 bpm, per-person errors, interval score/coverage/width, resource use and validity rate separately. The >10 bpm threshold is a diagnostic, not a medical standard. Missing activity groups are reported; no activity-balanced aggregate is produced if a predeclared group is absent. Bootstrap people, never overlapping windows.

For 90% intervals, IS90 = width + 20*max(lower-reference,0) + 20*max(reference-upper,0). Large intervals incur a width penalty. Optional skill is 1-loss/max(frozen_baseline_loss,1e-9); keep negative values. Baseline loss must be fixed before agent comparison. Valid runs rank above invalid runs if ranking is needed.

Record hypotheses, expected outcomes, code changes, commands/configs/seeds and evidence IDs. These substantive experiment records, not private reasoning, support a separate LLM process judge. Its rubric is `physiology-research-judge-v1`; numerical prediction loss remains authoritative and separate. Export trajectories with an explicit independent outer split (agent training/development/final evaluation). No post-training or RL is implemented here. Publicly downloadable data may have appeared in foundation-model pretraining; this is a retrospective release. Small cohorts and resampled windows do not establish field, clinical, or general research-agent validity.
