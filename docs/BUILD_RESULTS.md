# Benchmark build results — October 17, 2026

The controller now executes frozen source code, records an experiment history and scores generated forecasts. PLAN.md retains both sensor/product and benchmark scope; these implementation changes cover the benchmark.

## What ran

A deterministic synthetic recovery fixture supplies separate support, optional acquisition, development and test sessions for one virtual participant. No real recordings are used in these scores.

| Run | Initial development MAE | Final hidden MAE | Final 90% interval score |
| --- | --- | --- | --- |
| Persistence | 20 bpm | 20 bpm | 310 |
| Personalized linear fit | 0 bpm | 0 bpm | 10 |
| Development-only automatic selection | Chooses linear fit | 0 bpm | 10 |
| Scripted revision | 20 bpm | 0 bpm | 10 |
| Luna participant, one run | 12.8 bpm | 0 bpm | 42 |

The Luna participant received public observations, proposed source code and acquisition/evaluation actions, then revised using development feedback before submitting. Its initial slope cap reduced the observed decline and caused error. The revision removed the unsupported cap; point forecasts matched the simple hidden fixture, while wider intervals produced a worse interval score than the fitted baseline. No fine-tuning occurred. This demonstrates a functioning feedback path, not model superiority, benchmark difficulty, calibrated uncertainty or population generalization. Subagent observation access was instruction-limited; no hardened full-agent filesystem boundary was deployed.

## Data and execution status

The canonical CSV adapter audits supplied recordings and builds one-participant episodes with explicit provenance. A small unchanged PhysioNet HR file was downloaded and inspected; see DATA_AUDIT.md. It has not been converted into invented independent sessions or reported as a benchmark result.

Actual macOS execution, optional fitting, private-file denial at different locations, network denial and a bounded timeout were tested. The executor requires Python-startup host reads outside explicitly denied roots and provides only best-effort memory limits. It is a local prototype, not a hardened adversarial-code service. Docker was present but its daemon unavailable.

## Remaining decisive work

1. Audit whole source recordings and event alignment, choose a supported real-data forecast profile and freeze session/participant splits.
2. Add a hardened container/VM executor before untrusted multi-user campaigns; retain the existing execution protocol.
3. Supply an external judge model/configuration, validate its verdicts and perform a manual agreement audit.
4. Calibrate uncertainty, repeat model runs with inference resource accounting and test meaningful difficulty on development cases.
5. Enable Transfer and Sustain once recording coverage supports them; choose post-training only after valid baseline comparisons expose a repeatable failure.

## Linked campaign extension

A second pilot now runs Build → Investigate → Transfer → Sustain in one persistent workspace. It adds staged evidence, checkpoint submissions, condition-specific development feedback and private retention/forward-generalization matrices. The prior seven benchmark components remain the base architecture; real-data and judge calibration gates remain open.

Five conventional competitors completed three synthetic cases each (15 campaigns). The cases vary parameters within one declared synthetic family; these are not independent physiological participants or held-out model-family generalization tests.

| Conventional policy | Final MAE averaged across cases and conditions (bpm) |
| --- | --- |
| persistence | 55.951 |
| pooled_structure_search | 9.586 |
| recent_only_search | 14.437 |
| contextual_structure_search | 0.000 |
| contextual_redundant_acquisition | 16.746 |

In case 0, the recent-only competitor's short-condition error rose from 0 at Build to 32.504 bpm after adapting to the later session, despite achieving zero on that new condition. Contextual structure search retained zero on previously calibrated conditions. Redundant acquisitions consumed the same credits but did not provide calibration for new conditions. These checks establish that forgetting, useful acquisition and model structure are observable in the harness. The strongest conventional competitor can solve all supplied cases, so difficulty and post-training value are still unestablished.

Run artifacts: `.benchmark-runs/linked-campaign-3cases/report.md` and `report.json`, plus per-competitor private checkpoints and judge packets. The full test suite now passes 44 tests, including 8 campaign-specific tests. No new LLM participant or external judge was run for this extension.

## Integration with current shared main and Elo

The shared main also contains the independently developed `physbench/` PPG-DaLiA runner, sensor capture and dashboard from the earlier merged PR. The structural `benchmark/` runner complements those components. This change preserves that code and packages both runners. It does not rerun the Linux/RunPod real-data smoke test or claim new real-model results from the PR description.

Prediction/uncertainty Elo tables now summarize matched structural campaign outcomes. An offline `rate-physbench` command can also rate complete existing real-model result batches, applying the existing integrity gate and excluding infrastructure-affected matched cases. All models start equally; a fine-tuned model earns its rank from outcomes. See RATINGS.md for the versioned rules.
